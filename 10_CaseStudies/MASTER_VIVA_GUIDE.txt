GREEDY vs DP: THE ONE BIG QUESTION
================================================================================

                    GREEDY                      DYNAMIC PROGRAMMING
                    ------                      -------------------
Makes choices:      ONCE (no reconsideration)   CONSIDERS ALL choices, picks best
Subproblems:        Independent                 OVERLAPPING (same subproblem reused)
Proof needed:       Exchange argument / proof   Optimal substructure
Speed:              Generally FASTER            Slower but more powerful
When to use:        Local optimum = global opt  When greedy fails; count/min/max

TEST: Try a COUNTER-EXAMPLE for greedy.
      If you find one where greedy fails -> USE DP.
      Example: Knapsack (0/1) -> greedy by ratio FAILS -> use DP


================================================================================
BACKTRACKING vs DP vs BRUTE FORCE
================================================================================

BRUTE FORCE: Try ALL possibilities -> Exponential, no pruning
BACKTRACKING: Try possibilities but ABANDON early when constraint violated
              -> Better than brute force due to pruning
DP:  Avoid RE-SOLVING same subproblems -> Polynomial time

WHEN TO USE BACKTRACKING:
  -> You need ALL solutions (N-queens all arrangements)
  -> Constraint satisfaction (Sudoku, Graph Coloring)
  -> There is NO polynomial-time DP for it
  -> The problem has "trying + undoing" structure


================================================================================
COMPLEXITY QUICK REFERENCE
================================================================================

O(1)       Constant    -> Array index access, math formula
O(log n)   Log         -> Binary search, fast exponentiation
O(n)       Linear      -> Linear scan, Kadane's, BFS/DFS with adj list
O(n log n) Log-linear  -> Merge sort, Quick sort avg, Kruskal, Dijkstra (heap)
O(n^2)     Quadratic   -> Bubble/Selection/Insertion sort, LIS naive
O(n^2 * k) Cubic-ish   -> DP with 3 nested loops (MCM, Egg Drop)
O(2^n)     Exponential -> Brute force subsets, naive recursion
O(n!)      Factorial   -> Checking all permutations (N-queens brute)

MASTER THEOREM (For divide & conquer recurrences):
  T(n) = T(n/2)   + O(1)  -> O(log n)         [Binary Search]
  T(n) = 2T(n/2)  + O(n)  -> O(n log n)       [Merge Sort]
  T(n) = 2T(n/2)  + O(1)  -> O(n)             [Tree traversal]
  T(n) = T(n-1)   + O(1)  -> O(n)             [Linear recursion]
  T(n) = 2T(n-1)  + O(1)  -> O(2^n)           [Fibonacci naive]


================================================================================
COMMON VIVA QUESTIONS & ANSWERS
================================================================================

Q: Why use Greedy for Activity Selection?
A: Greedy works because choosing the activity that finishes EARLIEST leaves
   maximum time for future activities. No future choice can do better.

Q: Why does Dijkstra fail with negative weights?
A: Dijkstra marks a vertex as "finalized" once visited. A negative weight
   could later provide a shorter path to an already-finalized vertex.

Q: What is the difference between BFS and DFS?
A: BFS explores level by level (uses QUEUE), finds shortest path in unweighted graphs.
   DFS goes as deep as possible (uses STACK/RECURSION) before backtracking.

Q: What is memoization vs tabulation?
A: Memoization = Top-Down DP. Recursive function stores computed results.
   Tabulation = Bottom-Up DP. Iteratively fills a table from base cases up.
   Both have same time and space complexity.

Q: When does greedy work for Knapsack?
A: ONLY for Fractional Knapsack (can take partial items).
   For 0/1 Knapsack (must take completely or not at all), greedy fails and we need DP.

Q: Why is KMP better than Naive string matching?
A: Naive: O(n*m) because text pointer can go backward on mismatch.
   KMP: O(n+m) because LPS array tells us how far to skip. Text pointer NEVER goes back.

Q: What is the Subset Sum problem and its complexity?
A: Given integers, can a subset sum to target? DP solution: O(n * target).
   It's an NP-Complete problem for general inputs (exponential for unbounded).

Q: What is the difference between Kruskal and Prim?
A: Kruskal: EDGE-BASED. Sort all edges, add if no cycle forms (uses UNION-FIND).
            Better for SPARSE graphs.
   Prim: VERTEX-BASED. Grow tree from one vertex by adding min-weight edge.
         Better for DENSE graphs.

Q: What is backtracking and how does it differ from recursion?
A: All backtracking is recursive, but not all recursion is backtracking.
   Backtracking: Recursion + UNDOING choices when a path fails.
   (Like solving a maze: try, get stuck, come back, try another path)
